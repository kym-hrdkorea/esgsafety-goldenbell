## 8. 확인이 필요한 사항

### 8-1. `item_code` 재부여 정책 — **결정 필요**

이번 구성에서 6개 문항이 원래 회차를 벗어난다(1-03→2회차, 1-04→3회차, 4-11→3회차, 3-12→4회차, 5-03→4회차, 그리고 청렴 29문항은 `C1-xx` 체계).

- **A안(원번호 유지)**: 검토 시트와의 추적성이 완벽하지만, `item_code = '4-11'`이 3회차에 앉아 관리자 화면에서 혼란을 일으킨다. 더 결정적으로 **`db/validate-items.mjs`의 SQL 파싱 정규식 `^ \('([1-6]-[0-9]{2})',`가 `C1-xx` 코드에서 깨진다.**
- **B안(권장, 재부여)**: `item_code`를 `{회차}-{순번:02d}`로 새로 매기고, **검토 원번호를 `admin_note`에 기록**한다. `admin_note`는 앱 코드 어디에서도 참조되지 않음을 확인했으므로(참가자 응답에 절대 노출되지 않음) 규칙 2-1 위반 소지가 없다.

→ **B안을 권고하나, 결재 문서·검토 시트와의 대조 편의를 우선한다면 A안 + 검증기 정규식 수정도 가능하다. 어느 쪽인지 확정해 주십시오.**

### 8-2. 청렴 영역(`category`) 코드 설계 — **결정 필요**

현재 `CATEGORY_LABELS`는 안전 8종(F/G/H/O/E/K/L/S)이고 최근 커밋으로 **영역 아이콘 8종**이 '내 기록' 화면에 적용되어 있다.

- **1코드안**: `C`(청렴) 하나 → 아이콘 1종 추가로 끝나지만, '내 기록'의 영역별 정답률에서 **29문항이 한 덩어리**가 되어 피드백 해상도가 떨어진다.
- **3코드안**: 청탁금지(13) / 이해충돌(10) / 행동강령·신고(6) → 학습 피드백이 살아나지만 아이콘 3종 추가 + `design/copy.md` 라벨 3종 신설이 필요하다.

→ **3코드안을 권고한다.** 청렴 29문항의 법률 근거 분포가 정확히 이 3덩어리와 일치한다.
