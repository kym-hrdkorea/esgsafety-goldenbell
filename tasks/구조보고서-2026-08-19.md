## 3. 핵심 규칙 요약 (버그 위험 순)

1. **MC4/ORDER 좌표계 변환** — 제출값은 화면 표시 위치, 판정은 `choice_order[position]`으로 원본 index 환산, **저장은 원본 index**. 셔플은 세션 생성 시 1회만(`choice_order` 확정 저장, OX·SHORT는 NULL). 요청마다 재셔플·표시 위치 저장은 즉시 분석 불능으로 이어지는 최고 위험 지점. (`lib/grading.ts` 순수 함수 + 단위테스트 30개)
2. **서버 타이머** — `elapsed = now() − served_at` > 45s → timeout(오답, submitted=NULL, 해설은 정상 제공). `served_at`은 문항 실제 서빙 시 **NULL일 때만 1회 기록**(CAS) — 갱신되면 새로고침 무한 연장 구멍. 클라이언트 타이머·elapsed는 표시용/불신. 프런트는 만료 시 payload 없는 자동 제출로 서버 판정 유도.
3. **포인트·순위(N항)** — 정답 = `point_base + ROUND(point_time_bonus_max × 남은시간/제한시간)`(100~200P, 회차 만점 2,400P), 오답·timeout 0. **app_config에서 읽고 하드코딩·저장 금지**. 시간 요소는 served_at→answered_at만(해설 열람·총 소요시간 금지). score(정답 수)는 결과 `{score}/12`·성과분석용으로 병존 — 두 지표 혼용이 버그 소지. 최소 응시 회차는 `fn_min_rounds()` 단일 출처(종료 회차 ≤2 → 0, ≥3 → 3), `app_config.min_rounds_for_ranking` 직접 읽기 금지(lib/config.ts가 의도적으로 미노출). 부서 배지는 **departmentId 비교**(동명 부서 108/193).
4. **세션 수명주기** — 1인 1회차 1회(UNIQUE 제약이 경합 직렬화). 신규 생성은 `fn_create_quiz_session` 단일 트랜잭션(12행 검증 포함). 개방 게이트는 신규 생성에만 — in_progress 재개는 마감 후에도 허용(B4). 해설 단계 30분 방치 → expired(lazy + Cron 5분), 이어하기 불허, expired에도 `completed_at=now()` 기록(E항). 완료는 12번째 answer에서 즉시 확정(D항), `/next`·결과 조회는 멱등 복구 경로(`fn_reconcile_quiz_session` FOR UPDATE).
5. **채점 기타** — OX 단순 비교, ORDER 완전일치(부분점수 없음), SHORT 정규화 순서 고정(trim→공백 전제거→NFKC, 현재 `1-04` 1문항). 중복 제출은 `answered_at IS NULL` 조건 claim으로 멱등.
6. **성과측정 무결성** — measureCode/anchorCode/level은 참가자 응답에서 단계 무관 영구 제외. `/api/me/stats`는 category NULL(측정 문항) 집계 제외. matched/outcomes는 사전 12+사후 12 **완전대응 동일인만**, timeout=오답. 사전학습 효과군은 `viewed_at <= started_at`만.
7. **인증** — 참가자 5회/15분, 관리자 10회/10분 잠금(CAS 카운터). reset-pin은 failed_attempts 미증가·잠금 중 허용·세션 미발급·단일 401(열거 오라클 차단)·700ms 하한. 쿠키는 HMAC 서명 stateless(hq_session/hq_admin, 12h, 교차 401).

## 6. 정상 작동 확인 시 중점 점검 포인트 (영역별 정독 종합)

**T23 검증 시 우선 확인 (계약 핵심)**
1. **네트워크 응답 4종**: 답변 전 GET /item에 answer/explanation/legalRef 부재, measureCode/anchorCode/level 전 단계 부재, 45초 초과 제출의 서버 timeout 판정, 완료 세션 재응시 409.
2. **MC4 셔플 실효 검증(M항)**: 우회 플래그가 없으므로 SQL로 `quiz_session_item.choice_order` 직접 확인. 저장된 `submitted`가 원본 index인지도 함께.
3. **포인트 이중 구현 일치**: `v_round_score`(SQL) vs `calcItemPoints`(TS) — 동일 세션에서 결과 화면 포인트와 순위 뷰 포인트 대조.
4. **개시 절차**: 전 회차 일괄 `is_published=true` 전에 prelearning_body 6건 존재 재확인, 3회차 종료 전까지 `fn_min_rounds()=0`(순위 공백 없음, B-2) 확인.

**부하·배포 환경 이슈 (api 정독發)**
5. reset-throttle이 **인스턴스 로컬 메모리** — Vercel 다중 인스턴스에서 "전역 40/시간"이 인스턴스별로 늘어남. 100 VU 부하 시 실효 한도 확인.
6. HMAC 쿠키 세션 **revoke 불가**(12h) — PIN 재설정 후에도 기존 세션 유효. 파일럿 안내 시 인지 필요.
7. `/api/health` 공개+app_config 1행 노출, `/api/org/*` 무인증(조직도 전체 노출) — 의도 여부 확인. empNo 길이 상한 비대칭(reset-pin만 max 20).
8. Cron 2건: CRON_SECRET 미설정 시 fail-closed 401 정상 동작, refresh-rankings 60초 중복 스킵, expire-sessions 1,000행 초과 전량 순회.

**프런트 실기기 점검 (frontend 정독發)**
9. Pretendard가 **jsdelivr CDN** 의존 — 사내망 차단 시 폴백 동작 확인. BGM 파일(`/audio/bgm-*.mp3`) 배포 에셋 존재 여부.
10. 응시 화면 복귀 시나리오: 화면 잠금·앱 전환·iOS bfcache 복귀 후 타이머 재동기화(GET /item, served_at 미갱신), 만료 자동 제출 실패 시 수동 재시도 개방.
11. 대시보드 isMe가 total/average/round 탭에서 **닉네임 문자열 비교** — 유니크 제약 전제라 현재 안전하나 파일럿 데이터에서 배지 오표시 없는지 확인. 구 스냅샷(departmentId 부재) 부서 배지 미표시 동작.
12. 접근성 잔여(스크린리더): ShortItem label 부재, 선택 버튼 aria-pressed 부재, Timer aria-live 부재, 대시보드 탭 시맨틱 부재 — 사내 접근성 요구 수준에 따라 후속 여부 결정.
13. 미세 표시: 결과 "틀린 문제만 보기"에 timeout 포함(라벨 대비), 홈 참여 회차 분모에 미개방 회차 포함, SoundToggle 하이드레이션 1프레임 깜빡임, 관리자 일부 표 overflow-hidden.
