## 2. E2E 상세 — 계약 검증 증적

테스트 계정 `E2E점검계정`(사번 99900001)으로 1회차를 임시 공개해 전 구간 응시. **결과 10/12, 정답률 83.3%, 1680P.**

### 2-1. 정답 유출 방지 (CLAUDE.md 규칙 2)

답변 전 `GET /api/rounds/1/item` 실제 응답:

```json
{"seq":0,"totalItems":12,"itemType":"SHORT","stem":"...","choices":null,
 "remainingSec":45,"timeLimitSec":45,"phase":"answering"}
```

- `answer`·`explanation`·`legalRef` **부재** — 규칙 준수
- `measureCode`·`anchorCode`·`level` **부재** — 규칙 2-1(성과측정 무결성) 준수
- 해설 단계 진입 후에만 정답·해설·법령근거 노출 확인

### 2-2. 선택지 셔플 좌표계 (규칙 4)

세션 생성 시 `choice_order`가 1회 저장되고 이후 재셔플되지 않음을 DB로 확인.

| seq | 문항 | choice_order | 원본 answer | 화면 정답 위치 | 실제 화면 |
|---|---|---|---|---|---|
| 1 | 1-06 | `[1,3,2,0]` | 2 | 위치 2 (3번째) | 3번째 "C급" = 전기화재 정답 |
| 2 | 1-05 | `[3,1,0,2]` | 0 | 위치 2 (3번째) | 3번째 = 소화기 올바른 순서 |
| 5 | 1-12 | `[1,0,3,2]` | 1 | 위치 0 (1번째) | 1번째 = 소화기+단독경보형감지기 |

문항 출제 순서도 셔플됨(1-04, 1-06, 1-05, 1-11, 1-01, 1-12, …). OX·SHORT는 `choice_order=null`(규칙대로).

### 2-3. 서버 권위 타이머 (규칙 3)

- 11번 문항 무응답 방치 → **"시간이 초과되었습니다"** 표시, `is_timeout=true`·`is_correct=false`·`elapsed_ms=49394`(45초 초과)·`submitted=null`
- 시간초과도 해설은 정상 제공(규칙대로), 포인트 0
- `remainingSec`는 서버가 매 요청마다 계산해 내려줌

### 2-4. 포인트 산식 일치 (N항)

화면 표시 포인트와 `100 + ROUND(100 × (45000−elapsed_ms)/45000)` 계산이 **12문항 전부 일치**:

| seq | elapsed_ms | 계산 | 화면 |
|---|---|---|---|
| 0 | 36,537 | 119 | +119 |
| 1 | 23,835 | 147 | +147 |
| 3 | 10,409 | 177 | +177 |
| 11 | 11,208 | 175 | +175 |

합계 **1680P** = 결과 화면 표시값. SQL 뷰와 TS 구현(`lib/grading.ts`)이 어긋나지 않음을 실측 확인.

### 2-5. 세션 수명주기

- 12번째 답변 즉시 `status=completed`, `score=10`, `completed_at` 기록 (D항)
- 완료 후 `/round/1/quiz` 재접근 → 결과 화면으로 리다이렉트 (재응시 차단, 결정사항 #9)
- 타임아웃 문항은 `answered_at=null`이므로 확정 응답 11건 + 타임아웃 1건

### 2-6. 순위·통계

- 대시보드: 내 순위 1위, KST 기준시각 표시, "나" 배지, 탭 4종 정상

## 3. 발견 문제 및 조치

### 3-1. 해결 완료 — 개발환경 문제 2건 (코드 무관)

| # | 증상 | 원인 | 조치 |
|---|---|---|---|
| 1 | `pnpm` 명령 전부 실패 | corepack이 pnpm 11을 설치했으나, 저장소는 pnpm 10 기준. pnpm 11은 `package.json`의 `pnpm.onlyBuiltDependencies`를 무시 | `corepack prepare pnpm@10 --activate` + 루트에 `pnpm-workspace.yaml` 추가(빌드 승인 목록) |
| 2 | `pnpm test:prelearning` 실패 ("1회차 JSON·SQL 본문 불일치") | 이 PC의 `core.autocrlf=true`가 체크아웃을 CRLF로 변환 → 검증기가 SQL 리터럴 내 줄바꿈과 JSON `\n`을 비교하다 불일치 | 저장소 로컬 `git config core.autocrlf false` + 재체크아웃 |
| 3 | 로컬 `/api/health` 500 (`fetch failed`) | 사내망 TLS 검사 프록시의 자체서명 인증서(`SELF_SIGNED_CERT_IN_CHAIN`). 사용자 환경변수 `NODE_EXTRA_CA_CERTS=C:\certs\win-root-bundle.pem`이 있으나 도구로 띄운 dev 서버가 상속받지 못함 | dev 서버 기동 시 `NODE_EXTRA_CA_CERTS` 명시 |

**#3 재발 방지**: 로컬 개발 시 다음처럼 기동한다.

```bash
NODE_EXTRA_CA_CERTS=C:\certs\win-root-bundle.pem pnpm dev
```

PowerShell이면 `$env:NODE_EXTRA_CA_CERTS='C:\certs\win-root-bundle.pem'; pnpm dev`. Vercel 운영 환경은 무관(프로덕션 헬스 200 확인).
