# 비즈니스 규칙 명세

> 이 문서의 규칙은 구현 재량이 없다. 애매하면 코드를 짜지 말고 질문한다.

## 1. 인증

### 1.1 회원가입
| 필드 | 규칙 |
|---|---|
| 사번 | 숫자 문자열. 중복 시 거부(이미 가입됨 안내) |
| 닉네임 | 2~12자, 중복 불가, **가입 후 변경 불가** — 수정 API·UI를 만들지 않는다 |
| PIN | 숫자 4자리. `bcryptjs` cost 10으로 해시. 평문·로그 기록 금지 |
| 소속 | 기본은 아래 부서 항의 통합 검색으로 함께 선택. 폴백(목록 직접 선택) 시 `org_unit` 50개 중 선택, `optgroup`으로 본부/부설기관/소속기관/국외 EPS 구분 표시 |
| 부서 | **기본: 소속·부서 통합 검색**(2026-07-31 개선) — 소속명+부서명 토큰 AND 매칭, 결과는 `{소속} · {부서}` 표기. 동명 부서가 최다 32개 소속에 반복되므로 소속명 병기가 필수다. 폴백 시 선택된 소속의 `department`만 표시 |

- 비밀번호 확인 입력을 1회 더 받는다(오타 방지). PIN 재설정은 **사용자 자율 재설정**으로 제공한다(1.3) — addendum O항.
- `participant.org_unit_id`는 선택한 부서의 상위 소속으로 서버에서 채운다(클라이언트 값 신뢰 금지).

### 1.2 로그인
- 사번 + PIN 4자리.
- **실패 5회 → 15분 잠금** (`failed_attempts`, `locked_until`). 성공 시 `failed_attempts=0`.
- 4자리는 조합이 1만 개뿐이다. 잠금이 없으면 타인 계정 진입이 가능하고,
  재응시 불가 규칙 때문에 **피해자의 응시 기회가 소진된다.** 이 기능은 필수다.
- 세션 쿠키: httpOnly, sameSite=lax, secure, 유효기간 12시간.

### 1.3 비밀번호 재설정 (자율) — addendum O항
- `사번 + 닉네임 + 부서`가 모두 일치하면 새 PIN 4자리를 설정한다. `POST /api/auth/reset-pin`.
- **검증 실패는 `failed_attempts`를 올리지 않는다.** 공격자의 추측은 매번 다른 참가자 행을
  향하므로 계정별 카운터로는 막히지 않고, `lib/login-lock.ts`를 재사용하면 잠금 15분 연장·
  `last_login_at` 오염 버그가 따라온다. 정량 제동은 `lib/reset-throttle.ts`(IP·인스턴스 단위)가 맡는다.
- **잠금 중에도 재설정을 허용한다.** 잠금은 4자리 PIN 브루트포스를 막는 장치인데 이 엔드포인트는
  PIN 추측을 받지 않아 브루트포스를 진전시키지 못한다. 반대로 차단하면 "PIN 잊음 → 5회 실패 →
  잠김 → 재설정 필요"라는 가장 흔한 정상 경로에서 기능이 무력해진다.
- 성공 시 `password_hash`와 함께 `failed_attempts=0, locked_until=NULL`을 **같은 UPDATE로** 지운다.
  없으면 비밀번호를 바꾸고도 최대 15분간 로그인할 수 없다.
- **세션을 발급하지 않는다.** 성공 후 새 PIN으로 로그인해야 한다. 세션 쿠키는 서버 저장소가 없어
  취소 불가능한 12시간 자격증명이므로 로그인보다 약한 증명으로 발급하지 않는다.
- 새 PIN이 기존과 같은지 **검사하지 않는다.** 검사하면 "기존과 동일" 응답이 PIN 오라클이 되어
  아무것도 바꾸지 않고 현재 PIN을 알아낼 수 있다(피해자가 눈치채지 못하는 조용한 탈취).
- 닉네임은 **trim·소문자화하지 않고 그대로 비교한다.** 가입이 trim하지 않아 앞뒤 공백이 붙은
  닉네임이 저장될 수 있고, 여기서 다듬으면 그 사용자는 영구히 재설정할 수 없다.
- 이 기능이 감수하는 위험(R1~R9)과 대안 기각 근거는 addendum O항에 있다. **읽지 않고 수정하지 말 것.**

## 2. 회차 개방

- 이번 운영의 회차는 `1..6`이며, 7·8회차는 존재하지 않는 회차로 처리한다.

```
개방 조건 = is_published AND now() BETWEEN opens_at AND closes_at
```
- 월요일 00:00:00 ~ 금요일 23:59:59 (Asia/Seoul). 국외 EPS 센터 17개국 시차를 고려한 결정이다.
- 판정은 **항상 서버에서** 한다. 클라이언트 시각을 쓰지 않는다.
- 종료된 회차는 **복습 모드**로 전환: 문항·정답·해설 열람 가능, 점수 미반영, 재응시 불가.
- 아직 개방되지 않은 회차는 문항·사전학습 모두 접근 차단.
- **진행 중(`in_progress`) 세션의 재개는 회차 마감과 무관하다** — 금 23:59:59 직전에 시작한
  세션은 마감 후에도 이어서 진행할 수 있다(test-scenarios B4). 개방 게이트는 **신규 세션 생성**에만
  건다. `POST /session`·`GET /item`·`POST /answer`·`POST /next` 모두 이 기준으로 동작한다.
- **`is_published` 운영 방식**(2026-08-04, 리뷰 A-5): 개방은 일정이 단독으로 결정한다.
  개시 전 1회만 6회차를 일괄 `true`로 올리고(전제: `prelearning_body` 6건 모두 채워짐),
  이후 `false`로 내리는 것은 **긴급 중단** 한 가지 경우뿐이다.
  매주 수동으로 켜는 방식은 실패해도 화면·로그에 드러나지 않아 폐기했다.
  개방 상태는 관리자 화면 '회차 개방 상태'에서 확인한다.

## 3. 응시 세션

### 3.1 세션 생성 (1회차당 1회, 재응시 불가)
1. `quiz_session`에 해당 (participant, round) 행이 이미 있으면 **새로 만들지 않는다.**
   - `status='in_progress'` → 이어서 진행(같은 세션 재개)
   - `status IN ('completed','expired')` → 결과 화면으로 리다이렉트
2. 신규 생성 시 그 회차 12문항을 조회해 **문항 순서를 셔플**하고
   `quiz_session_item` 12행을 `seq=0..11`로 미리 생성한다.
3. MC4·ORDER 문항은 **선택지 순서도 셔플**해 `choice_order`에 저장한다.
   - `choice_order = [2,0,3,1]` → 화면 1번 위치에 원본 index 2를 표시
   - OX·SHORT는 `NULL`
4. `served_at`은 이 시점에 채우지 않는다. 문항을 실제로 내보낼 때 채운다.

### 3.2 문항 서빙
- `current_index`에 해당하는 `quiz_session_item`을 조회한다.
- `served_at IS NULL`이면 `served_at = now()`로 기록한다. **이미 값이 있으면 절대 갱신하지 않는다.**
  (갱신하면 새로고침으로 타이머를 무한 연장할 수 있다)
- 응답 payload에 포함: 문항 stem, 표시순으로 재배열된 choices, 남은 시간(초), 진행률
- 응답 payload 필드는 **`answered_at` 상태에 따라 달라진다.**
  - `answered_at IS NULL` → `answer`·`explanation`·`legal_ref` **제외**
  - `answered_at IS NOT NULL` 또는 `is_timeout` → 위 3개 **포함**(해설 화면 새로고침 복구용)
- `measure_code` / `anchor_code` / `level`은 **단계 무관 영구 제외**.
  노출되면 참가자가 측정 문항을 식별해 성과 데이터가 오염되고, 그 사실이 화면에 드러나지 않는다.

### 3.3 제한시간 (문항당 45초)
```
elapsed = now() - served_at
if elapsed > 45s  →  is_timeout = true, is_correct = false, submitted = null
```
- 만료된 문항도 **해설은 정상 제공**한다. 사용자는 "시간 초과" 표시 + 해설 + [다음 문항] 버튼을 본다.
- 제출 요청이 들어왔더라도 서버 판정으로 45초를 넘었으면 timeout으로 처리한다.
- 클라이언트 타이머는 표시용. 0이 되면 자동으로 제출 요청을 보내되, 판정은 서버가 한다.

### 3.4 해설 단계 방치 (30분)
```
now() - last_activity_at > 30분  →  session.status = 'expired'
```
- 남은 미응답 문항 전부를 `is_timeout=true, is_correct=false`로 확정한다.
- **이어하기는 허용하지 않는다.** 해당 회차는 그 점수로 종료된다.
- `last_activity_at`은 문항 서빙·제출·다음 버튼 클릭 시 갱신한다.
- 만료 처리는 lazy 방식으로 한다: 접근 시점에 검사해 만료시키고,
  추가로 `/api/cron/expire-sessions`가 주기적으로 정리한다.

### 3.5 완료
- 12문항 모두 처리되면 `status='completed'`, `completed_at=now()`, `score` 확정.
- 이후 결과 화면만 접근 가능.

## 4. 채점 규칙 (`lib/grading.ts` — 단위테스트 필수)

| 유형 | 제출 형식 | 판정 |
|---|---|---|
| `OX` | `true` / `false` | `submitted === answer` |
| `MC4` | 화면 표시 위치(0~3) | `choice_order[position] === answer` |
| `ORDER` | 화면 표시 위치 배열 | 각 위치를 원본 index로 변환 후 `answer` 배열과 완전일치 |
| `SHORT` | 문자열 | 정규화 후 `answer` 배열에 포함되는지 |

**MC4 변환 예시** — 정답 원본 index=2, `choice_order=[3,2,0,1]`
사용자가 화면 2번째(position=1)를 골랐다면 `choice_order[1]=2` → **정답**.
저장은 원본 index(`2`)로 한다. 화면 위치를 저장하면 분석이 불가능해진다.

**SHORT 정규화 순서**
1. 앞뒤 공백 제거 → 2. 모든 공백 제거 → 3. `NFKC` 유니코드 정규화
4. `answer` 배열의 각 값에도 동일 정규화를 적용해 비교
- 부분점수·유사도 매칭은 **하지 않는다.** 정확한 정답만 인정한다.
- 미매칭 응답은 관리자 화면에 모아 사후 수동 인정할 수 있게 조회만 제공한다.
- 현재 SHORT 문항은 `1-04`(아차사고) 1개뿐이다.

## 5. 순위 규칙

### 5.0 포인트 (순위·포상 전용) — addendum N항 (2026-07-30)

순위와 포상은 정답 수(`score`)가 아니라 **포인트**로 산정한다. 만점자 다수 발생에 대비한 변별 장치다.

```
문항 포인트 = 정답:        point_base + ROUND(point_time_bonus_max × 남은시간 / 제한시간)
              오답·시간초과: 0
남은시간 = GREATEST(제한시간ms - elapsed_ms, 0)
회차 포인트 = 12문항 포인트 합 (기본값 기준 만점 2,400P)
```

- 기본값 `point_base=100`, `point_time_bonus_max=100` → 문항당 100~200P.
  두 값은 **`app_config`에서 읽는다**(`point_base`, `point_time_bonus_max`). 하드코딩 금지(규칙 7).
- 포인트는 **저장하지 않는다.** `is_correct`·`elapsed_ms`에서 집계 시점에 계산하는 파생값이다.
  스키마 변경 없음.
- **시간 요소는 문항별 답변 시간(`served_at`→`answered_at`)만 반영한다.**
  해설 열람 시간·세션 총 소요시간은 어떤 점수·순위에도 반영하지 않는다 —
  해설을 오래 읽어도 불이익이 없어야 한다(학습 효과 보호, 5.2 개정 취지).
- 적용 범위: **대시보드 순위 4종 + 포상.**
  `score`(정답 수)는 결과 화면(`{score} / 12`)·내 기록·복습·성과분석(v_matched_pre_post,
  v_item_stats 등)의 기준으로 유지한다. 성과측정은 정답 여부 기반이므로 포인트의 영향을 받지 않는다.
- 화면 표기: 정답 배너 `+{points} SCORE`, 결과 화면 `획득 포인트 {points}P` 병기 (`design/copy.md`).

### 5.1 최소 응시 회차 (결정③)
```
공개 회차 수 <= 2  →  임계값 0 (조건 없음)
공개 회차 수 >= 3  →  임계값 3 (3회 이상 응시자만 순위 대상)
```
- **누적 순위와 평균 순위 모두에 동일 적용**한다. `fn_min_rounds()` 함수로 구현되어 있다.
- 캠페인 1·2주차에는 3회 응시가 물리적으로 불가능하므로 조건을 걸지 않는다.
- 조건 미달자는 순위표에 나오지 않지만 **본인 점수는 항상 본인에게 표시**한다.

### 5.2 대시보드 4개 순위 (N항 개정: 산정 기준은 5.0의 포인트)
| 순위 | 산정 | 조건 | 정렬 |
|---|---|---|---|
| 전체 회차 누적 | `SUM(회차 포인트)` | 3회 이상 | 포인트 DESC |
| 회차별 | 해당 회차 포인트 | 없음 | 포인트 DESC |
| 평균 | `AVG(회차 포인트)` | 3회 이상 | 평균 DESC, **응시 회차 DESC** |
| 부서 | 부서 응시자 `AVG(회차 포인트)` | **참여자 3명 이상** | 평균 DESC, 참여자 DESC |

- 표시: 기본 **5행**, [더보기]로 **20행**까지 확장.
- **동점자는 공동 순위**(`RANK()` → 1, 2, 2, 4). 공동 순위 때문에 20행을 넘으면 그대로 표시한다.
- **세션 총 소요시간(해설 열람 시간 포함) 기준 정렬은 사용하지 않는다.**
  시간 변별은 5.0의 문항별 포인트로만 반영한다 — 해설 읽기를 방해하지 않기 위한
  원래 결정의 취지를 유지한다(addendum N항).
- 본인·본인 부서는 순위 밖이어도 **별도 카드로 항상 표시**한다("나: 37위 / 우리 부서: 12위").
- 부서 순위 지표는 **평균 포인트**다. 정원 데이터가 없으므로 참여율은 산식에 넣지 않는다.

### 5.3 집계 갱신
- 대시보드는 `ranking_snapshot`만 읽는다. 순위 뷰를 직접 조회하면 안 된다.
- `/api/cron/refresh-rankings`가 뷰 → snapshot으로 적재한다. 주기 60초.
- 세션 완료 시 즉시 갱신을 트리거해도 되지만, **60초 이내 중복 실행은 스킵**한다.

## 6. 사전학습
- 회차 문항과 **동시 공개**(월요일 00:00)한다.
- 사전학습 페이지 진입 시 `prelearning_view`에 upsert(참가자+회차 유니크).
- 이 로그로 "퀴즈 시작 전 열람자 vs 미열람자 정답률"을 산출한다. `viewed_at <= quiz_session.started_at`인 경우만 열람자로 분류한다. 퀴즈 시작 후 다시 본 사전학습은 기록에는 남지만 이 연관지표의 열람군에는 포함하지 않는다.
- 종료된 회차의 사전학습 자료도 계속 열람 가능하다.

### 6.1 성과측정 KPI (T18)
- 1차 KPI의 대응 표본은 사전 `M01~M12`와 사후 `M01P~M12P`를 **각각 12개 모두 확정**한 동일인이다.
- 일부 문항만 확정한 참가자는 참여·응답 원본에는 남기지만 `v_matched_pre_post`와 1차 KPI에서는 제외한다.
- `is_timeout=true`인 문항은 `is_correct=false`인 오답으로 계산한다. 시간초과를 미응답으로 빼서 정답률을 높이지 않는다.
- 개인별 정답률은 `확정 정답 수 ÷ 12 × 100`, 개인별 향상폭은 `사후 정답률 - 사전 정답률`이다.
- `v_matched_summary`는 완전대응 표본의 대응 표본 수, 사전·사후 평균, 개인별 향상폭 평균·중앙값, 향상자 수·비율을 산출한다.
- `v_measure_pair_stats`는 같은 완전대응 표본에서 M01~M12 문항쌍별 사전·사후 정답률과 향상폭을 산출한다.
- A1·A2 회차별 정답률과 T01~T04 전이문항 정답률은 보조지표다. 사전학습 열람 효과도 인과효과가 아닌 연관지표로 표시한다.

## 7. 관리자
- 조회 + CSV 내려받기만 구현한다. **문항 CRUD UI는 만들지 않는다**(Supabase 대시보드에서 직접 편집).
- CSV 대상: 응답 원본, 회차별 점수, 문항 통계, 동일인 대조, 성과 요약, 히트맵, 참여 지표.
- CSV는 UTF-8 BOM 포함으로 출력한다(Excel 한글 깨짐 방지).
- 관리자 세션은 참가자와 **쿠키 이름을 분리**한다(`path=/` 동일). → addendum G-2항
